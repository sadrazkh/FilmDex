# FilmDex

پوشه‌ها را یک‌بار می‌خواند، نام فایل‌ها و پوشه‌ها را نگه می‌دارد، و بعداً — با درایوِ وصل‌نبوده — می‌گویی
دنبال چه اسمی هستی و هر چه شبیهش باشد را با **درصد شباهت** نشان می‌دهد. برای این‌که قبل از دانلود یک
فیلم مطمئن شوی تکراری نیست.

## اجرا

```bash
dotnet build -c Release
```

بعد `src/FilmDex.App/bin/Release/net10.0-windows/FilmDex.App.exe` را اجرا کن. نیازی به نصب چیزی نیست؛
فقط .NET 10.

می‌توانی پوشه را روی فایل اجرایی هم بکشی و رها کنی — همان لحظه اضافه و اسکن می‌شود:

```bash
FilmDex.App.exe "E:\Movies"
```

## چطور کار می‌کند

**کتابخانه‌ها.** هر پوشه‌ای که اضافه می‌کنی یک کتابخانه است. یک‌بار به‌صورت بازگشتی خوانده می‌شود و
نام‌ها در یک پایگاه‌دادهٔ SQLite می‌مانند. بعد از آن، درایو می‌تواند وصل نباشد؛ جستجو آفلاین کار می‌کند.
هر وقت خواستی «اسکن مجدد» بزن — عکس تازه جای عکس قبلی را می‌گیرد، یعنی فایلی که پاک شده باشد از
فهرست هم می‌رود.

چه چیزی ثبت می‌شود: فایل‌های ویدئویی (mkv، mp4، avi، m2ts و …) و نام پوشه‌هایی که فیلم داخلشان است.
زیرنویس، عکس، nfo و فایل‌های ریز sample/trailer نه.

**جستجو.** حین تایپ جستجو می‌شود. هر نتیجه دو درصد دارد:

| ستون | چه چیزی را مقایسه می‌کند |
|---|---|
| **٪ عنوان** | عنوان تمیزشده. یعنی `The.Matrix.1999.1080p.BluRay.x264-GROUP.mkv` می‌شود «the matrix» با سال ۱۹۹۹، و بعد مقایسه می‌شود. ترتیب کلمات مهم نیست و غلط تایپی را هم تحمل می‌کند. |
| **٪ نام خام** | خودِ نام فایل، همان‌طور که روی دیسک است. برای وقتی که پارسرِ عنوان اسم عجیبی را بد تمیز کند. |

اسلایدر آستانه روی **بیشترِ این دو** فیلتر می‌کند، پس یک نتیجه از هر دو راه می‌تواند خودش را نشان دهد.
اگر سال دو طرف با هم فرق داشته باشد، امتیاز کم می‌شود و کنار سال یک علامت هشدار می‌آید — نتیجه حذف
نمی‌شود، چون همان‌جاست که آدم باید خودش نگاه کند.

نام‌های فارسی هم درست کار می‌کنند: `ي` عربی و `ی` فارسی، `ك` و `ک`، ارقام فارسی و عربی، و نیم‌فاصله
همه یکسان‌سازی می‌شوند. کلمه‌هایی مثل «دوبله»، «فارسی»، «زیرنویس» و پیشوند سایت‌های دانلود
(`www.Film2Movie.Us.…`) از عنوان برداشته می‌شوند.

## داده‌ها کجاست

`%LOCALAPPDATA%\FilmDex\filmdex.db`

اگر متغیر محیطی `FILMDEX_DB` را ست کنی، همان مسیر استفاده می‌شود — برای وقتی که یک آرشیو دوم یا یک
پایگاه‌دادهٔ آزمایشی می‌خواهی. اگر برنامه به مشکلی بخورد، دلیلش در `last-error.log` کنار همان فایل
نوشته می‌شود.

دکمهٔ **«تحلیل مجدد نام‌ها»** عنوان‌های ذخیره‌شده را از روی همان نام‌ها دوباره حساب می‌کند، بدون خواندن
دیسک. یعنی اگر قواعد تشخیص تگ بهتر شد، لازم نیست همهٔ هاردها را دوباره وصل کنی.

## ساختار

| پروژه | چه کاری می‌کند |
|---|---|
| `FilmDex.Core` | تحلیل نام، الگوریتم شباهت، ایندکس در حافظه، SQLite، اسکنر پوشه. هیچ ارجاعی به WPF ندارد. |
| `FilmDex.App` | فقط رابط کاربری (WPF + Material Design 3). |
| `FilmDex.Core.Tests` | ۶۵ تست روی هسته. |

```bash
dotnet test
```

جستجو روی ایندکسِ در حافظه انجام می‌شود، نه روی دیسک. برای این‌که با ده‌ها هزار نام هم هر ضربهٔ کیبورد
سریع بماند، اول یک پیش‌فیلتر دو-حرفی (bigram) کاندیداها را کوتاه می‌کند و بعد امتیازدهی کامل — موازی —
روی همان‌ها اجرا می‌شود. یک تست تضمین می‌کند این پیش‌فیلتر هیچ نتیجه‌ای را که امتیازدهی کامل پیدا
می‌کرد، پنهان نکند.

## بعداً

ستون `CategoryId` در پایگاه‌داده از حالا هست ولی استفاده نمی‌شود؛ دسته‌بندی مرحلهٔ بعد است.
